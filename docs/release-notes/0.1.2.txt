修复：让每一次更新都能抵达

- 更新流量不再固守启动那一刻的线路。每一次请求都会在当下重新择路：先经由正在运行的 Tesseract 核心，再试系统代理，最后直连；一条路不通，便顺势转入下一条。
- 检查更新改为读取发布版本中经签名的校验清单，不再受 GitHub API 频率限制的掣肘。
- 每个发布文件依次尝试 github.com、ghfast.top 与 gh-proxy.com，并记住上一次走通的来源，下次优先启用。
- 下载中断后从断点续传，最多重试 5 次。
- 信任的依据始终如一：Ed25519 签名的清单与安装包的 SHA-256 校验，决定什么可以被安装，无论它来自哪条线路。
- 更新失败时，设置页会给出前往发布页手动安装的入口；按钮上只留「操作失败」四字，详细原因在下方，标题不再被挤成一列。
- 更新失败的原因现在会写入 bridge.log（只记录错误类别与各条线路的结果，不记录地址），排查有迹可循。

改进：启动时，言其所为

- 首个启动阶段依情形命名：Vanguard 或 Sentinel 中已有节点时显示「加载节点」；两层皆空、需要等待 Bastion 收集公共节点时，才显示「收集节点」。
- 运行药丸与日志页的运行摘要不再标注「1/3」这样的步数，进度条本身已足以讲述进度。九种界面语言同步更新。

新增：说明，以你的语言写就

- 更新说明现在只呈现当前界面语言的那一段；没有对应语言时显示英文。

提示

- 从 0.1.0 或 0.1.1 应用内更新仍可能失败，因为这两个版本沿用旧的更新程序。如遇此情况，请从发布页下载安装包手动安装一次；此后的更新都将走新的通道。

[en_US]
Fixed: updates that find their way

- Update traffic no longer clings to the route it found at startup. Every request now chooses its path in the moment: through the running Tesseract core first, then the system proxy, then a direct connection, falling through to the next whenever one is closed.
- Update checks now read the release's signed checksum manifest instead of the rate-limited GitHub API.
- Each release file is tried from github.com, ghfast.top and gh-proxy.com in turn, and the source that worked last is tried first next time.
- Interrupted downloads resume where they left off, for up to 5 attempts.
- Trust is unchanged: an Ed25519-signed manifest and the installer's SHA-256 decide what gets installed, whichever route delivered it.
- When an update fails, Settings offers the release page for a manual install. The button stays brief and the full reason sits beneath it, instead of squeezing the title into a single column.
- bridge.log now records why an update failed (error classes and each route's outcome, never an address).

Improved: startup says what it is doing

- The first startup phase is named for what it does: "Loading nodes" when Vanguard or Sentinel already holds nodes, and "Collecting nodes" only when both are empty and Bastion must gather public ones.
- The run pill and the Logs run summary drop the "1/3" step count; the progress fill already tells that story. All nine interface languages are updated.

New: release notes in your language

- Release notes now show only the section in your interface language, with English as the fallback.

Note

- Updating in-app from 0.1.0 or 0.1.1 may still fail, because those versions carry the old updater. If it does, download the installer from the release page and install it once; every update after that takes the new path.
