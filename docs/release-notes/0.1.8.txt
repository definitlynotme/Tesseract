[zh_CN]
升级：代理核心 Mihomo 1.19.34

- 内置的代理核心从 Mihomo 1.19.27 升级到 1.19.34。1.19.27 自带的 TUN 协议栈有缺陷，上游从 1.19.28 起修复；这次升级同时带来之后各版的修复，其中包括：TUN 模式下 DNS 劫持偶尔发回全零或过期的应答、TUN 自动路由规则的问题、重新载入配置后假 IP 的分配记录丢失、低于 1 毫秒的测速被当成失败，以及 crypto/tls 的几项安全修复。
- 新核心不再把节点集合里的节点列进自己的节点总表，按名字查询或测速这样的节点会得到「不存在」。Bastion 层的节点正是以节点集合载入的，所以 Tesseract 现在改从节点集合本身读取和测速这些节点，结果与以前完全相同：启动、出口检测、故障判定和切换都照常工作。

关于更新

- 已安装 0.1.4 到 0.1.7 的，可以直接在应用内更新到本版本。点「立即更新」后 Tesseract 会关闭，并显示「正在更新 Tesseract…」窗口；在「用户帐户控制」中选择「是」即可。如果没有看到授权提示，点任务栏上闪烁的按钮。
- 0.1.0 到 0.1.3 仍需在浏览器中打开 github.com/definitlynotme/Tesseract/releases/latest，下载 Tesseract-Setup-0.1.8-win-x64.exe 手动安装一次。

[en_US]
Upgraded: the proxy core, now Mihomo 1.19.34

- The built-in proxy core moves from Mihomo 1.19.27 to 1.19.34. The TUN stack in 1.19.27 has a defect that upstream fixed from 1.19.28 on, and the upgrade also brings the fixes of every release since, among them: DNS hijacking in TUN mode that could send zero-filled or stale replies, a problem in the TUN auto-route rules, fake-IP allocations lost when the configuration is reloaded, a latency test under one millisecond counted as a failure, and several crypto/tls security fixes.
- The new core no longer lists the nodes of a node set among its own nodes, and asking for or testing such a node by name answers "not found". The Bastion tier's nodes are loaded as a node set, so Tesseract now reads and tests them through the node set itself, with the same results as before: start, the exit check, failure judgement and switching all work as they did.

About updating

- If you have 0.1.4 to 0.1.7, you can update to this version from inside the app. After "Update now", Tesseract closes and an "Updating Tesseract…" window appears: choose Yes in User Account Control. If you see no prompt, click the flashing button on the taskbar.
- 0.1.0 to 0.1.3 still need one install by hand: open github.com/definitlynotme/Tesseract/releases/latest in your browser and download Tesseract-Setup-0.1.8-win-x64.exe.
