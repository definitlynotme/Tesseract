[zh_CN]
修复：应用内更新终于能装上

- 0.1.0 到 0.1.3 的每一次应用内更新都停在「安装包已就绪」。安装包已下载并通过校验，但外壳回复「由我关闭并安装」时少带了一个字段，后台据此拒收，安装程序从未启动。现在回复按约定完整发送，后台也不会再因缺这个字段而拒收。
- 外壳的测试现在对外壳发出的每一帧执行与后台相同的校验：后台会拒收的帧，测试就会失败。
- 交接没有完成时，设置页不再停在「安装包已就绪」：会说明安装没有开始，并给出「立即更新」重试和「前往发布页」手动安装；侧栏底部显示「有新版本」，不再一直显示「更新已就绪」。安装程序没能启动时，设置页会说明更新失败，并给出「前往发布页」。
- 交接被拒时，shell.log 会记下后台给出的错误码。
- 手动安装新版本后的首次启动，不再显示之前没装成的那个版本的更新说明。
- 为更新退出时，恢复系统代理与防火墙规则有了足够的时间。以前只有不到 0.1 秒，需要恢复时常常来不及完成，安装程序便会被拒绝启动。
- 便携版不再在应用内安装更新：它会指向发布页，不会在 Program Files 里另装一份、而便携版本身却始终停在旧版本。

修复：Tesseract 在托盘里运行时也能安装

- 安装程序会先关闭正在运行的 Tesseract，再开始安装。以前它承诺「安装时会先关闭它」，实际上关不掉在后台运行的部分，安装随即中止并还原，什么也没装上。现在它像注销时一样请 Tesseract 自己退出：系统代理与防火墙规则照常恢复，然后才开始复制文件。
- 安装程序为安装而关闭的 Tesseract，装完后会重新打开；安装没有完成时（例如在授权提示时选了「否」）也一样，不再让它就此消失。
- 从本版本起，安装程序关闭 Tesseract 时，它像从托盘退出一样走完整个退出流程，托盘里不会再留下失效的图标。以前它把这当成注销或关机，没走完退出流程就结束了。
- Tesseract 以管理员身份运行时，安装程序没有权限关闭它，会立即提示先从托盘退出，不再白等。
- 在登录用户的会话里从命令行静默安装（/SILENT 或 /VERYSILENT）时也会先关闭 Tesseract，装完后重新打开它；加上 /NORESTARTAPPLICATIONS 时，安装成功后保持关闭。以 SYSTEM 身份在后台部署时无法关闭用户的 Tesseract，安装会像以前一样中止。命令行里带引号、以反斜杠结尾的 /DIR= 路径不再吞掉后面的开关。

重要：请手动安装一次

- 0.1.0 到 0.1.3 仍按旧代码交接，在应用内更新到本版本同样会停在「安装包已就绪」。请在浏览器中打开 github.com/definitlynotme/Tesseract/releases/latest，下载 Tesseract-Setup-0.1.4-win-x64.exe 手动安装一次（Tesseract 在托盘里运行也没关系，安装程序会先关闭它，装完再打开；它以管理员身份运行时，先从托盘退出它）；从本版本起，应用内更新可以正常完成。
- 已经点过「立即更新」的话，安装包已经下载并通过了校验，不必再去浏览器下载：打开「运行日志」，点「⋯」→「打开日志文件夹」，进入 updates 文件夹，双击 Tesseract-Setup-0.1.4-win-x64.exe。

[en_US]
Fixed: in-app updates now install

- In 0.1.0 to 0.1.3, every in-app update stopped at "Installer ready". The installer was downloaded and verified, but when the shell replied that it would close the app and install, it left out one field, the background service refused the reply, and the installer never started. The reply is now complete, and the service no longer refuses it for that field.
- The shell's tests now apply the service's own checks to every frame the shell sends: a frame the service would refuse fails the tests.
- When a hand-off does not finish, Settings no longer stops at "Installer ready". It says the install did not start and offers "Update now" to try again and "Open release page" to install by hand. The sidebar shows the new version instead of "Update ready". When the installer could not be started, Settings says the update failed and offers "Open release page".
- shell.log now records the error code when the service refuses a hand-off.
- After you install a newer version by hand, its first start no longer shows the notes of a version that failed to install earlier.
- Quitting for an update now leaves enough time to restore the system proxy and firewall rules. It used to get less than 0.1 seconds, so a needed restore often did not finish and the installer was refused.
- The portable build no longer installs updates from inside the app. It points to the release page instead of installing a second copy into Program Files while the portable copy stays on the old version.

Fixed: installing while Tesseract runs in the tray

- Setup now closes a running Tesseract before it installs. It always promised to, but it could not close the part that runs in the background, so the install stopped and rolled back without installing anything. Now it asks Tesseract to quit the way signing out does: the system proxy and firewall rules are restored as usual, and only then are files copied.
- Setup opens the Tesseract it closed again once it is done, also when the install does not finish (for example, you answer No at the permission prompt), instead of leaving it closed.
- From this version on, when Setup closes Tesseract, it goes through its whole exit as when you quit from the tray, and no stale icon is left in the tray. It used to take that close for a sign-out or shutdown and ended before its exit was done.
- When Tesseract runs as administrator, Setup is not allowed to close it. It now says at once to quit Tesseract from the tray first, instead of waiting in vain.
- A silent install from the command line in the signed-in user's session (/SILENT or /VERYSILENT) also closes Tesseract first and opens it again afterwards; with /NORESTARTAPPLICATIONS it stays closed once the install succeeds. A deployment that runs as SYSTEM in the background cannot close the user's Tesseract, so that install still stops, as before. A quoted /DIR= path that ends in a backslash no longer swallows the switches after it.

Important: install this version by hand once

- 0.1.0 to 0.1.3 still hand off with their old code, so updating to this version from inside the app also stops at "Installer ready". Open github.com/definitlynotme/Tesseract/releases/latest in your browser, download Tesseract-Setup-0.1.4-win-x64.exe and install it once (Tesseract may keep running in the tray: Setup closes it first and opens it again afterwards. If it runs as administrator, quit it from the tray first.). From this version on, in-app updates complete.
- If you already clicked "Update now", the installer is already downloaded and verified, and you don't need the browser: open Logs, choose ⋯ → Open log folder, open the updates folder and double-click Tesseract-Setup-0.1.4-win-x64.exe.
